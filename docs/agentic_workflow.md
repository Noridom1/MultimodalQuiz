# Agentic Quiz Generation Workflow

This document summarizes the agentic, knowledge-graph-driven quiz generation workflow implemented in this repository, how components interact, and where to look in the codebase.

## Overview

The system converts a source document into a knowledge graph, plans question topics using an agentic planner, and generates multimodal quiz items (text + images) using LLMs and an image provider. The key goals are: ground questions in extracted facts, maximize concept coverage, attach multi-chunk context to prompts, and produce high-quality, image-grounded questions.

## Main components

- `src/knowledge/*` — Knowledge graph and retrieval
  - `retriever.py`: Topic/context retrieval, returns TopicContext with `concepts`, `concept_chunks`, and `images`.
  - `validator.py`: Graph validation rules (topic labels, grounding counts).

- `src/planner/*` — Agentic planner
  - `topic_planner.py`: Uses `LLMClient` to produce `QuestionPlan` objects per topic. Key behaviors:
    - Greedy allocation to maximize unique concept coverage across topics.
    - Attaches `knowledge_context` (top-N chunks per plan) so generator gets grounded text.
    - Parametrized by `difficulty_distribution` and `reasoning_type`.
  - `topic_prompt_templates.py`: Prompt templates that render topic context (now up to 5 chunks per concept).

- `src/generator/*` — Prompt building, image generation, and question generation
  - `prompt_builder.py`: Builds `question_prompt` and `image_prompt`. The image prompt is produced by `build_image_prompt_via_llm` (LLM returns a short natural-language instruction). `build_question_prompt` formats multi-chunk `knowledge_context` for the question LLM.
  - `image_gen.py`: Submits prompts to image provider; now supports submission retries and resilient polling.
  - `question_gen.py`: Calls the LLM (via `LLMClient`) to generate question JSON, validates and repairs outputs.
  - `orchestrator.py`: Orchestrates end-to-end generation. Recent updates:
    - Logs prompts and raw LLM responses to `outputs/.../generation/prompt_logs`.
    - Uses a shared `LLMClient` instance and calls `build_image_prompt_via_llm`.
    - Submits image generation tasks in parallel (ThreadPoolExecutor) to speed runs, then generates questions per image result.

- `src/utils/llm.py` — LLM client abstraction and provider implementations (OpenAI, Gemini, Mistral). Central source of model/provider configuration (`configs/model_config.yaml`).

## Config & Secrets

- `configs/model_config.yaml` controls `llm` and `image_generation` provider settings, model names, api_key_env names, and timeouts. Ensure provider API keys (e.g., `MISTRAL_API_KEY`, `FREEPIK_API_KEY`) are set in your environment.

## Robustness & Design choices

- Single shared `LLMClient` is preferred and now injected so planner, image-prompt builder, and question generator use the same provider/config.
- Image generation now has submission retries with exponential backoff and poll failure thresholds.
- Parallel image generation reduces end-to-end latency by submitting multiple provider tasks concurrently.
- The planner enforces `tested_fact_block_id` for traceability and attaches multi-chunk contexts to reduce hallucination.

## Logs, prompts, and debugging

- `orchestrator` writes per-question prompt logs to `outputs/<run_id>/generation/prompt_logs/question_<N>.txt` containing:
  - `knowledge_context`, `question_prompt`, `image_prompt`, and raw LLM responses for auditing.
- When image/API failures occur, check provider dashboard and the environment keys; 403 typically indicates auth/permission issues.

## Running the pipeline

Basic run (example):
```
python scripts/run_pipeline.py data/processed/<doc>/.../file.md --num-questions 10
```
Use `--mock-image --mock-question` to avoid external calls during testing.
